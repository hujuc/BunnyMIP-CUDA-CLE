Volumetric Maximum Intensity Projection (MIP) with CUDA Programming
1 - Introduction
The Stanford Bunny (Figure 1) is perhaps the most iconic test model in the history of computer 
graphics. Originally scanned in 1994, it has served as the baseline for algorithms ranging from mesh 
simplification to ray tracing. In this assignment, we move beyond the surface mesh and work with the 
Stanford Bunny CT Scan, a volumetric dataset that captures the internal density of the model, 
not just its “skin.”
Figure 1: The Standford Bunny (left) and its CT scan (right)
1.1 - The Volumetric Dataset
Unlike a 3D mesh composed of triangles, a CT (Computed Tomography) scan consists of a series 
of 2D cross-sectional “slices” (Figure 1). For this project, you are provided with 361 slices, each a 
512×512 grayscale image. When stacked together, these slices form a 3D grid of volume elements, 
or voxels.
This volume is represented in memory as a contiguous 1D array of uint16_t values, where each value 
represents the density at a specific point (𝑥,𝑦,𝑧). The total volume dimensions are 512×512×361.
1.2 - The Processing Pipeline
To transform this raw “cloud” of density data into a high-quality 2D raster image, your program must 
implement a three-stage pipeline. Each stage presents a unique parallelization challenge in CUDA.
1) Thresholding  (Point  Operation): Raw CT scans often contain “air noise”, low-intensity 
values captured in the space surrounding the object. You will implement a threshold function 
that sets any voxel below a specific intensity to zero. This “cleans” the volume and ensures that 
the final projection is focused solely on the bunny.

2) 3D Gaussian Blur (Stencil Operation): To prevent single high-intensity noise pixels from 
dominating the final image, you will apply a 3D Gaussian blur. This stage requires a spatial 
convolution where each voxel’s value is recalculated based on a weighted average of its 3×3×
3 neighborhood.
3) Maximum Intensity Projection (MIP): MIP is a volume rendering method used to visualize 
3D data on a 2D plane. It simulates firing parallel rays through the volume. For each pixel on the 
screen, the algorithm finds the maximum voxel intensity encountered along the corresponding 
ray.
By implementing this on the GPU, you will take a process that takes seconds on a CPU and accelerate 
it to real-time speeds, allowing for interactive rotation and visualization of the bunny’s internal 
structure.
2 - Requirements
Each group is assigned the task of porting the sequential volume processing pipeline to the GPU 
using the CUDA framework.
2.1 - Base Code and Environment
A reference implementation is provided in C/C++, located in the directory src/bunnyMIP. This code 
contains the sequential logic for loading the volume, thresholding, blurring, and projecting the data.
Your implementation work must be contained within:
• src/device-bunnyMIP.cu
You are expected to write the kernel definitions, handle memory allocation on the device (VRAM), 
and manage the data transfer between the Host (CPU) and Device (GPU).
2.2 - Validation and Correctness
To verify the success of your implementation, your application must perform a validation check. 
The raster image generated by your CUDA kernels must be compared against the “Gold Standard” 
image generated by the host. The device-calculated MIP must not differ significantly from the host-
calculated version.
2.3 - Performance Evaluation: Speedup Analysis
A portion of your final report must be dedicated to a quantitative analysis of your GPU implemen-
tation. You must demonstrate that your parallelization efforts resulted in a measurable performance 
gain over the sequential reference.
2.4 - Command Line Interface (CLI)
Your application must be dynamic. It must parse and accept the following input parameters to 
influence the final rendering:
• --threshold: Defines the intensity floor. Any voxel 𝑣<threshold must be set to 0.
• --sigma: Defines the standard deviation (𝜎) used to calculate the Gaussian weights.
• --roll, --pitch, --yaw: Defines the rotation of the volume in degrees.
These parameters must be used to update the kernels at runtime. Specifically, the rotation angles 
should be used to construct a 3×3 rotation matrix 𝑅, which is then utilized by the MIP kernel for 
backward mapping.

2.5.1 - Shared Resource Etiquette
The banana server is a shared resource used by multiple student groups simultaneously. To ensure 
a stable and fair environment for everyone, please adhere to the following rules:
• Responsible Usage: Be mindful of your VRAM and CPU usage. Avoid leaving large memory 
allocations active if you are not actively debugging.
• No VSCode SSH: You are prohibited from using the VSCode Remote-SSH extension.
‣The Reason: This extension is notoriously resource-heavy. It spawns multiple background 
Node.js “zombie” processes that consume significant RAM and CPU cycles on the host, 
even after you disconnect. This can drastically degrade the performance of the server for 
other users.
• Alternative  Tools: Please use lightweight terminal-based editors (such as vim or nano) or 
develop locally and transfer your files using scp or rsync. If you prefer a GUI, use a local editor 
and synchronize your code via Git or SFTP.

may result in your processes being terminated without warning or, in extreme cases, the suspension of 
your server access. Treat the hardware with respect; it’s the only bunny-processing power we’ve got!
